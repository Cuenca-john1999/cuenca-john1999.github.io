# CV Builder

Public route: `cv-builder/?lang=es|en|de`. Deterministic keyword matching, not an eligibility or experience-duration assessment. All printable professional claims derive from common-evidence.json and cv.json. Up to 12 selected skills; same two-page renderer as static CVs. Personal mode is not authenticated; contact input is local, not stored or published. ZIP contains custom CV and explicitly selected same-origin public PDFs. Tests: `node tools/test_cv_builder.mjs` and `node tools/generate_market_dossiers.mjs --check`.

The builder mounts natively at `#cv-builder` in all main portfolios. The original standalone route remains available. Profiles preselect up to eight skills (maximum twelve). Offer comparison, personal contact input and ZIP are progressively disclosed. Changing the PDF language does not change the surrounding portfolio. CSS is scoped. Browser checks cover each market and the standalone route.

Context engine: versioned multilingual task patterns and a separate transferable evidence layer. School science support is a builder-only focus. It promotes documented STEM teaching into page one while preserving the static CVs. Context links are suggestions, not equivalence claims. No trained language model has been installed. Regression cases include school-lab, research and explicit GMP requirements. Source excerpts are rendered with textContent; no offer is transmitted or persisted.

Requirement priority is a conservative clause-level hint (required, duty, preferred, unspecified or explicitly not required); it is not a comprehensive logical or legal interpretation. The UI exposes original snippets for task matches. Job descriptions are capped at 60,000 characters each. Further neural matching should be opt-in and run locally in a worker with a calibrated multilingual embedding model. E5-small is a candidate (MIT; 512-token input limit), so chunk full offers and precompute the public evidence index. Benchmark by job family, language, paraphrase, negation, distractors and long descriptions before enabling neural suggestions. Keep model output to evidence IDs, validate against the catalogue, and never publish private source documents. Browser inference must fall back to current rules on unavailable model, unsupported hardware, or failed download. No neural weights or generative model are included in this revision.

Semantic v1: optional real multilingual E5-small inference, pinned model revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78, Transformers.js 3.8.1, INT8, WASM in a dedicated module worker. Public evidence text is embedded at runtime and cached in worker memory; the model uses browser asset cache. All non-negated offer passages are chunked locally; query/passage prefixes and mean-pooling normalized vectors are used. No offer data is persisted or sent to inference APIs. Model/runtime assets are downloaded from Hugging Face and jsDelivr (network requests reveal normal connection metadata). The experimental cosine threshold .79 and top-three-per-passage retrieval are not calibrated confidence scores. Results are advisory and must be selected explicitly; facts and known gaps are separate. Quick analysis remains available if cancelled or unavailable. Tests cover synthetic vectors and a live browser download/inference smoke test; broader multilingual precision/recall benchmarking is still required. Current semantic analysis covers the first vacancy only; quick comparison covers both.

Benchmark (2026-11-28): 13 diagnostic cases including paraphrases of public adverts, synthetic multilingual, negation, sector ambiguity, irrelevant prose and long-tail controls. The quick regression asserts expected evidence and alerts. The real Chromium worker benchmark records expected-evidence coverage, additional suggestions for review, latency and threshold alternatives. The small curated fixture is not a representative validation set; do not describe coverage as overall model accuracy or tune and evaluate on the same cases. Threshold .79 remains experimental pending results.
